# Inventory from the script

Use one asset registry shared by rendering and the production browser. Counts derived only from a user's current playthrough miss conditional images.

## Asset brief

Each asset records:

- Stable ID; category (background, bust, object, interface); name and intended filename.
- Character/location reference and source status, separating approved appearance from proposed staging.
- Concrete composition, framing, expression, posture, orientation, crop and transparency requirements.
- Base asset or pose, variant relationship, production status and available preview file.
- Reason for the drawing, plus all scene/passage uses and branch conditions derived from the script.

For busts, specify brows, gaze, mouth and body posture instead of a bare emotional adjective. Maintain distinguishing physical details from the character sheet. Do not mirror asymmetric anatomy automatically.

For backgrounds, distinguish a location from its shots. Count new backgrounds, redraws and simple presentation changes separately. For objects, distinguish a new visual state from movement of the same image. For UI, count the reusable frame once rather than once per passage.

## Browser and outputs

Provide search and filters for category, owner/location and production status. Each brief links back to isolated scene previews, and each scene links to its brief. Include printable briefs and inventory/use exports. Mark spoilers and show which context a preview represents.

Track unused proposals separately. A proposed image is not approved or delivered simply because it appears in a registry. All unique referenced images count once even if reused across routes; all written branches must contribute to the use index.

Validate missing references, conflicting IDs, dangling base relationships, incomplete briefs and coverage of conditional actors. Keep branches explicit rather than guessing assets from keywords in prose.
